# Review, November 2026

Decisions made on `feature/enhancements-v2` that are not obvious from the design file. Each one names the source that settled it. Production `main` was not changed.

## Japanese featured title

The heading `VisionMax フリート管理プラットフォーム` carried `word-break: keep-all`. MDN defines `keep-all` as “word breaks should not be used for CJK text” ([MDN `word-break`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/word-break)). The katakana run is one unbreakable string. Measured on the built page:

- At 375px the heading box was 415px wide inside a card that ends at 355px. The card’s `overflow: hidden` clipped the title, the paragraph, and the tech chips.
- At 1440px the heading box stayed in its column, but the last glyph painted at x=832, about 240px past the heading, and ran under the dashboard.

`word-break: normal` plus the existing `text-wrap: balance` on `.display` does wrap the string, and it also splits words. Chromium and WebKit at 1440 produced `VisionMax フリート` / `管理プラットフォー` / `ム`. Chrome’s internationalization note says short Japanese text should break on a phrase boundary (文節), and that a `<wbr>` or a zero-width space is the manual way to place that boundary when automatic detection is wrong ([Chrome, CSS i18n features](https://developer.chrome.com/blog/css-i18n-features)).

`word-break: auto-phrase` is that automatic detection. It is in Chromium since 119. It is not in Firefox through 163, and stable Safari does not have it; Safari Technology Preview 246 only enabled it as a preview ([WebKit release notes](https://webkit.org/blog/18128/release-notes-for-safari-technology-preview-246/), [Can I use](https://caniuse.com/mdn-css_properties_word-break_auto-phrase)). A Chromium-only value would leave iPhone and Firefox on the mid-word breaks.

The heading keeps `keep-all` and the Japanese dictionary stores one U+200B before `プラットフォーム`. The component renders that character as `<wbr>`, so the character is not copied or read aloud. With only the space and that `<wbr>` as break points, Chromium, WebKit, and Firefox all set the same three lines when the column is narrow or the type is large:

```
VisionMax
フリート管理
プラットフォーム
```

At 768px the whole title still fits on one line, so the break is unused. `text-wrap: balance` does not invent extra breaks, because `keep-all` removed the per-character opportunities ([MDN `text-wrap`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-wrap)).

The text column also has `min-width: 0`. For a grid item, `min-width: auto` is the content’s minimum size, which is what let the unbreakable string widen the single column below the `lg` breakpoint ([MDN `min-width`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-width)). Chinese, English, and Korean titles already fitted. Removing `min-width: 0` again does not change the English page height, so those locales keep their pixels. The required visual baselines that change are the Japanese page at 375 and at 1440 in light mode: the title is three lines instead of a clipped run, and at 1440 it no longer paints over the dashboard. The full-matrix dark and 768 baselines were already shorter than the current page for English and Korean as well, so they were left as they were.

WCAG 2.2 success criterion 1.4.10 Reflow asks for content at a width of 320 CSS pixels without two-dimensional scrolling and without loss of information ([Understanding Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)). Clipping the title failed that, even though `body { overflow-x: clip }` hid the overflow from the page-level scroll check.

The same scan did not find another heading whose glyphs leave its box. The hero and the contact title looked like they did, because `SplitWords` keeps a screen-reader copy beside the visual words. The visible words sit inside the heading.

## Hero underline

The coral line under the highlighted words is one SVG path with `pathLength="1"`. A single `stroke-dasharray` number is both the dash and the gap: SVG 2 says an odd-length list is repeated until it is even, so `5` is the same pattern as `5,5` ([SVG 2, stroke-dasharray](https://www.w3.org/TR/SVG2/painting.html#StrokeDasharrayProperty)). The old rule `stroke-dasharray: 1` on a path of author length 1 therefore painted a gap through the middle of the word. Production `main` has that same markup. Reduced motion never added `js-motion`, so the gap was invisible there. Pause leaves `js-motion` on, so the gap stayed while motion was paused.

`pathLength` exists so the author length, not the browser’s geometry, drives dash offsets ([SVG 2, pathLength](https://www.w3.org/TR/SVG2/paths.html#PathLengthAttribute)). `getTotalLength()` on this path still returns about 194.85 in Chromium, and a dash array of that geometric length still opens a hole once `vector-effect: non-scaling-stroke` stretches the curve. `stroke-dasharray: 1 0` is a solid line whose offset does not hide it, so it cannot draw in. `stroke-dasharray: 2.4` and `3` do not finish the stroke on WebKit.

`stroke-dasharray: 2` with `pathLength="1"` means a dash of 2 and a gap of 2. The path is only length 1, so at offset 0 the gap starts after the path and the line is continuous. Animating `stroke-dashoffset` from 2 to 0 draws it from the left. The timing is the original one: 1.1s, `cubic-bezier(0.65, 0, 0.35, 1)`, delay 0.95s. The rule applies only while `js-motion` and `data-loops="on"` are both set, so reduced motion and the pause toggle show the finished line. Checked on Chromium, Firefox, and WebKit: offset 2 is a cap at the right end, the middle grows from the left, and offset 0 is one continuous line.

## Speculation Rules

Chromium’s Speculation Rules can prefetch a likely next page ([Chrome, prerendering](https://developer.chrome.com/docs/web-platform/prerender-pages)). Two things ruled them out here.

WebKit’s document prefetcher logs a console error and refuses the request unless the URL is HTTPS ([WebKit `DocumentPrefetcher.cpp`](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/loader/DocumentPrefetcher.cpp)). CI and local `next start` are HTTP, and the end-to-end suite fails on any console error.

The rules also prefetched `/` before the language cookie was updated. `next.config.ts` redirects `/` from the `NEXT_LOCALE` cookie. The prefetched response was the English page, so choosing 繁體中文 stayed on `/en`.

## Scrolling, canvas, and the viewport

Lenis runs only for a fine pointer on Chromium, including Edge. Firefox and Safari keep their own scrolling. Detecting Firefox with `CSS.supports("-moz-appearance", "none")` is wrong here: Chromium implements that prefixed property, so the check would turn Lenis off everywhere. The user-agent and `navigator.vendor` checks are the ones that separate the engines. A coarse pointer also skips Lenis, so a phone uses native scrolling.

The horizon canvas already pauses when it is off-screen or the document is hidden. Its device-pixel ratio is capped at 1.5 for a coarse pointer, Firefox, or `navigator.connection.saveData`, and at 2 otherwise. Frames are about 30fps in the modest cases and about 50fps otherwise. `saveData` is the data-saver hint ([MDN `NetworkInformation.saveData`](https://developer.mozilla.org/en-US/docs/Web/API/NetworkInformation/saveData)). The visual tests hide the canvas, so the cap does not move a baseline.

The hero uses `min-h-[100svh]`, not `100vh` or `100dvh`. MDN defines `vh` as the large viewport (`lvh`), which includes the space the mobile URL bar covers, and `svh` as the small viewport, which stays put when that bar is showing. `dvh` changes while the bar shows and hides, and MDN warns that the resize during scroll is a layout and performance cost ([MDN, CSS length](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)).

`theme-color` is `#f7f6f2` in light and `#060a14` in dark, the same values as `--bg`, through the viewport export ([MDN `theme-color`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/theme-color)). Next.js writes that from the `viewport` object ([Next.js, metadata and OG images](https://nextjs.org/docs/app/getting-started/metadata-and-og-images)). The same page in this install is `node_modules/next/dist/docs/01-app/01-getting-started/14-metadata-and-og-images.md`.

`content-visibility: auto` was not added. It skips rendering of off-screen content ([MDN `content-visibility`](https://developer.mozilla.org/en-US/docs/Web/CSS/content-visibility)), and the full-page screenshots then photograph blank sections.

`prefers-reduced-transparency: reduce` sets `backdrop-filter` to `none`. The default blur is unchanged ([MDN `prefers-reduced-transparency`](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-transparency)).

No `beforeunload` listener and no `Cache-Control: no-store` were added. Nothing on the page was blocking the back-forward cache, so there was no fix to make ([web.dev, back/forward cache](https://web.dev/articles/bfcache)).

## Search and structured data

The page is one schema.org `@graph` of `Person`, `WebSite`, and `ProfilePage` ([schema.org/Person](https://schema.org/Person), [WebSite](https://schema.org/WebSite), [ProfilePage](https://schema.org/ProfilePage)). Google’s intro asks for structured data that matches the visible page ([Google Search Central, structured data](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data)). `sameAs` is the LinkedIn and CakeResume URLs from the résumé. `knowsAbout` is the tool list that is also on the page. WebRTC is a feature on the résumé, not a specialty, so it is not in `knowsAbout`. There is no email, no GitHub URL, and no `alumniOf`, because education was removed from the page. `WebSite.inLanguage` is only `zh-Hant-TW` and `en`.

Japanese and Korean stay `noindex, follow` and out of the sitemap and the hreflang cluster until a native reader signs `docs/content-review.md`. `noindex` is the supported way to keep a URL out of Google’s index ([Google Search Central, block indexing](https://developers.google.com/search/docs/crawling-indexing/block-indexing)). `x-default` points at `/en`, the locale a visitor gets when none of the indexable languages match ([Google Search Central, localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions)).

`robots.txt` in production allows `*` and the assistant crawlers, and disallows `/` for the training crawlers named in `lib/metadata.ts` (GPTBot, ClaudeBot, CCBot, Google-Extended, Applebot-Extended, Bytespider, meta-externalagent). Google documents `Google-Extended` as a standalone token for Gemini Apps and Vertex AI. Disallowing it does not change inclusion or ranking in Google Search ([Google crawler overview](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers)). Non-production builds disallow every agent, so previews are not indexed. `/llms.txt` is a short résumé summary with the same facts and no email. It is a convenience file for assistants, not a ranking signal.

The email address is assembled in the browser after a click. `scripts/check-no-email.mjs` rejects a static copy of the address, a `mailto:` link, or `@gmail.com`.

## Contrast

WCAG 2.2 criterion 1.4.3 requires 4.5:1 for normal text and 3:1 for large text. Text that is pure decoration is exempt ([Understanding Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)). Criterion 1.4.11 requires 3:1 for meaningful non-text UI, and exempts decorative graphics ([Understanding Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)).

Measured relative luminance, not the rounded figure in `docs/design.md`:

| Pair | Ratio |
| --- | --- |
| muted `#5A6480` on bg `#F7F6F2` | 5.44 |
| muted on bg-2 `#EFEEE8` | 5.06 |
| primary `#2456F0` on bg | 5.30 |
| ink-2 `#27324F` on bg | 11.73 |
| dark muted `#8D99B6` on `#060A14` | 6.94 |
| dark primary `#7099FF` on `#060A14` | 7.25 |
| warm `#FF7A57` on light bg | 2.38 |
| warm dark `#FF9473` on dark bg | 9.17 |

The text colors used for body, labels, and links clear 4.5:1. `docs/design.md` says muted-on-bg is about 6:1; the measured value is 5.44, which still passes. Warm on a light background is 2.38:1. It is used for the underline, the logo dot, and decorative strokes, not for a sentence. Darkening it would be a new accent. It stays.

The WebKit color-contrast failure during a motion-on scroll was the reveal animation still at partial opacity. The test now waits until every `[data-reveal]` has settled. The colors themselves were not changed.

## Firefox in CI

Playwright’s image runs the browsers as root by default, which turns off the Chromium sandbox ([Playwright, Docker](https://playwright.dev/docs/docker)). In this job Firefox still refused to start: `HOME` was `/github/home`, owned by another user, and its content sandbox failed `clone` with `EPERM`. Firefox’s own message says to set `HOME=/root`. The job sets `HOME=/root` and `MOZ_DISABLE_CONTENT_SANDBOX=1` on the end-to-end step only.

## Left as they are

These looked like bugs in a bounding-box scan and are not:

- The skill marquee is wider than the viewport on purpose, inside `overflow: hidden`.
- The header wordmark is `max-xs:sr-only` below 480px. The logo mark remains.
- The desktop nav has both the warm underline and the active dot. Both are part of the current design.
- Card glow blobs sit outside their box and are clipped by the card.
- Header controls from 360px to 900px do not overlap or leave the viewport, including the Japanese language button.
- Focus rings on the hero button are drawn outside `overflow: hidden` and stay visible.
